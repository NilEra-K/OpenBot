# UI 与逻辑分离硬性约束

> 源自 ARCHITECTURE.md §5（协议纯度）与 §8（渲染层）。以下七条是**硬规则**：
> 违反任何一条在 code review 中一票否决，不进入"建议"范畴。
> 本文件适用于 P2 Vue 渲染层、内核事件设计、以及一切新增功能。

## 七铁律

1. **状态归属二分**
   - 归**内核**的事实：七族事件可表达的一切——roster、transcript、任务与产物、Box 状态与 caps、审批。
   - 归**渲染层**的局部态：当前视图、选中项、抽屉开合、输入草稿、过滤条件。
   - 局部态**永不上行**，丢弃无代价；内核事实不复制第二份可写副本。

2. **单向流**
   - 命令进（`POST /api`）、事件出（SSE/WS）。
   - 内核永不发 UI 指令——「打开弹窗 / 刷新视图 / 选中某项」不进协议；UI 对事件如何反应是渲染层自治。
   - 渲染层不直改内核状态，只能发命令。

3. **派生计算归位**
   - 会进协议的派生量（未读数、磁盘压力判定、图谱聚合）由**内核**算——它是事实。
   - 纯表现派生（排序、分组、配色、格式化）由**渲染层**算。
   - 同一条数据两边各算一个口径，必错。

4. **乐观更新带 nonce**
   - 渲染层可乐观渲染，但必须标 `pending`，以 nonce 关联内核事件回填或回滚。
   - 幂等账本顺便解决 UI 侧去重——重试不产生双条目。

5. **视图可重建（试金石）**
   - 任何视图都是 transcript/JSONL + 事件流的**纯函数投影**。
   - 回放 / 时间旅行天然可用——做不到 = 解耦不干净，返工。

6. **测试对称**
   - 内核测试零 DOM、零 Electron。
   - 渲染层测试对**内存版 transport 客户端**跑，无 Electron——mock 网关与 mock llm / mock box 同列。

7. **壳等价判据**
   - cli 与 desktop 共用同一命令面。
   - 任何功能「只有 desktop 能用」= 解耦已破，**当 bug 处理**。

## 协议纯度（三条补充）

- 协议里只有**领域事实与命令**，永远没有 UI 指令（见铁律 2）。
- 错误与状态传**稳定 code**（如 `BOX_SNAPSHOT_UNSUPPORTED`），不传文案；文案与多语言归渲染层。
- 内核代码里不出现 UI 字符串（按钮文字、提示语、视图名）。

## 对 prototype.html 的适用说明

prototype.html 是视觉母版：它的 JS 是演示脚本，**不受**上述约束追溯（它本就是 P2 重建的底稿）。
但 P2 用 Vue 重建五视图时，必须逐条对照本清单执行；原型中已按铁律预演的部分（如审批事件、caps 禁用态、乐观发送）在重建时保持同一语义。
